# AEO Intent-Based Practices (150+)

## Informational intent

1. Answer the question in the first 40–60 words.
2. Use definition format for “what is” queries.
3. Use explanation format for “how does X work.”
4. Use “why” format for reason queries (2–3 reasons).
5. Provide a clear, factual answer before any CTA.
6. Use neutral tone (not sales-heavy) for pure informational.
7. Use internal links to related guides, not only to shop.
8. Use “learn more” or “see our guide” for deeper dives.
9. Use tables or lists for “types of,” “examples of.”
10. Use one main concept per section.
11. Use citations or “according to” when citing data.
12. Use “experts say” or “research shows” when appropriate.
13. Avoid pushing a product in the first 2 paragraphs for informational queries.
14. Use “in summary” or “bottom line” at the end of the section.
15. Use educational subheadings (What is, How it works, Types).
16. Use diagrams or step-by-step when it helps understanding.
17. Use “beginners” or “explained simply” when the query implies that.
18. Use comparison only to clarify concepts, not to sell.
19. Use “myth vs fact” when the topic has misconceptions.
20. Use “frequently asked” or “common questions” for FAQ blocks.
21. Target one primary informational query per section.
22. Use schema (FAQPage, Article) for informational content.
23. Use breadcrumbs that reflect the topic path.
24. Use meta description that answers the question in one line.
25. Use title that includes the question or main concept.
26. Use “guide,” “explained,” “101” in title when appropriate.
27. Use internal links to commercial pages after the answer.
28. Use “next steps” or “ready to try” before CTA.
29. Use word count that matches depth (300–600 for definition, 800+ for guide).
30. Use “see also” for related informational pages.

## Commercial (comparison / best / buy) intent

31. Use “best,” “top,” “compare” in H1 or H2 when the query has that intent.
32. Use a clear criteria section (what we looked at).
33. Use a ranked list or comparison table.
34. Use “best for [use case]” in the recommendation.
35. Use pros and cons per option when comparing.
36. Use price or “starting at” when relevant (no fake prices).
37. Use “our pick” or “editor’s choice” with a short reason.
38. Use “also consider” or “runner-up” for alternatives.
39. Use CTA after the comparison (e.g. “Try StreamStickPro”).
40. Use internal links to product/shop pages.
41. Use schema (Product, Offer) when you have real products.
42. Use “review,” “tested,” “compared” in meta when accurate.
43. Use trust signals (trial, support, guarantee) near CTA.
44. Use “who it’s for” or “best for” per option.
45. Use a short “how we chose” or methodology when you have criteria.
46. Use consistent structure (name, pros, cons, best for).
47. Use “vs” in H2 for comparison queries.
48. Use “2026” or current year for “best 2026” queries.
49. Use “reddit” or “reviews” in content when you cite them.
50. Use “worth it” or “value” when the query implies cost concern.
51. Use “free trial” or “no commitment” when you offer it.
52. Use “under $X” when the query has a budget.
53. Use “for beginners” or “easy” when the query implies that.
54. Use “for [device]” when the query is device-specific.
55. Use “near me” or “[city]” when the query is local.
56. Use “alternatives” when the query is “X alternatives.”
57. Use “deals” or “discount” only when you have a real offer.
58. Use “buy” or “get” in CTA, not only “learn more.”
59. Use one primary CTA per page (e.g. Start free trial, Shop).
60. Use urgency only when true (“limited spots,” “offer ends”).

## Transactional (setup / how-to / fix) intent

61. Use step-by-step for “how to set up,” “how to install.”
62. Use numbered steps (1, 2, 3) for procedures.
63. Use “you’ll need” or “before you start” for prerequisites.
64. Use screenshots or video when it helps (and add alt/caption).
65. Use “troubleshooting” or “common issues” after the main steps.
66. Use “if X doesn’t work, try Y” for error handling.
67. Use “test” or “verify” as the last step.
68. Use HowTo schema for setup pages.
69. Use “in about 10 minutes” or time estimate when accurate.
70. Use “on [device]” in the title or H1 when device-specific.
71. Use “without [constraint]” when the query has that (e.g. “without cable”).
72. Use “for beginners” when the query implies that.
73. Use one task per page (one setup, one fix).
74. Use internal links to product or credentials page where relevant.
75. Use “next: [related task]” at the end.
76. Use “need help?” or support link after troubleshooting.
77. Use consistent terminology (e.g. “credentials” not “login” in one place and “credentials” in another).
78. Use “enter,” “click,” “select” for UI steps.
79. Use “you should see” for confirmation steps.
80. Use “don’t” or “avoid” for common mistakes.
81. Use “optional” only for steps that are truly optional.
82. Use “required” for steps that must be done.
83. Use “repeat for each device” when multi-device.
84. Use “save” or “write down” when user needs to keep info.
85. Use “copy” or “paste” when applicable.
86. Use “refresh” or “restart” when that fixes the issue.
87. Use “clear cache” or “reinstall” when relevant.
88. Use “contact support” when the user can’t fix it.
89. Use “still not working?” with a short checklist.
90. Use FAQ after the steps for “why did X happen.”

## Mixed intent (informational + commercial)

91. Answer the question first (1–2 paragraphs), then add recommendation.
92. Use “if you’re looking to try one” or “to get started” before CTA.
93. Use “our recommendation” or “we suggest” after the answer.
94. Use one CTA per page for mixed intent (e.g. free trial).
95. Use internal links to both guides and shop.
96. Use “learn more” and “get started” in the same page.
97. Use “best for most people” or “best value” in the recommendation.
98. Use trust signals (trial, support) near the CTA.
99. Use “no commitment” or “cancel anytime” when true.
100. Use “see our full guide” for deeper informational content.
101. Use “compare plans” or “view options” for commercial next step.
102. Use breadcrumb that reflects both topic and product (e.g. IPTV > Best IPTV).
103. Use meta description that answers + one line CTA.
104. Use title that includes the question and brand.
105. Use schema that matches the primary intent (FAQ + Product when both).
106. Use “summary” or “quick answer” before the longer explanation.
107. Use “in short” for the direct answer, then “in detail” below.
108. Use “who should consider” to segment audience.
109. Use “next steps” with both “read more” and “try now” when relevant.
110. Use “related guides” and “shop” in the same section.

## Navigational intent

111. Use brand name in title and H1 when the query is “[brand].”
112. Use “official” or “home” when the query is navigational.
113. Use clear site structure (nav, breadcrumbs) for “[brand] [product].”
114. Use one primary page per entity (one homepage, one shop).
115. Use canonical to avoid duplicate “brand” pages.
116. Use internal links from homepage to key pages (shop, guides).
117. Use “login,” “account,” “support” in nav when you have them.
118. Use “blog” or “guides” in nav for content.
119. Use footer with key links (terms, privacy, contact).
120. Use sitelinks (via structure and internal links) for brand queries.

## Local intent

121. Use “[city]” or “[region]” in title and H1 for local queries.
122. Use “in [city],” “for [city],” “near [city]” in P1.
123. Use location in meta description.
124. Use LocalBusiness or areaServed in schema when relevant.
125. Use “available in [city]” or “ships to [city]” when true.
126. Use “serving [region]” in trust or CTA.
127. Use location pages (e.g. /l/usa/iptv/houston) for “[topic] [city].”
128. Use breadcrumb: Home > [Country] > [Topic] > [City].
129. Use internal links from location pages to shop and pillars.
130. Use “near me” in content when you have a local offer.
131. Use consistent location format (city name, state/country).
132. Use one page per location when you have location-specific content.
133. Use hreflang or regional targeting when you have multiple regions.
134. Use “nationwide” or “ships to USA/Canada/UK” when accurate.
135. Use “local support” or “local delivery” only when true.

## Seasonal / time intent

136. Use “2026” or current year in title for “best 2026” queries.
137. Use “updated [month/year]” in content when you refresh.
138. Use dateModified in schema when you update.
139. Use “this year” or “current” when the query implies freshness.
140. Use “new” or “latest” only when the product/feature is new.
141. Use “Black Friday,” “Cyber Monday” only when you have an offer.
142. Use “spring,” “fall” only when you have seasonal content.
143. Use “back to school,” “holiday” when relevant and accurate.
144. Use “just launched” only when true.
145. Use “coming soon” only when you have a date.
146. Use “last updated” in the byline or footer when you change the page.
147. Use “as of [date]” when citing time-sensitive data.
148. Use “currently” for present-state claims.
149. Use “in 2026” in the answer when the query has the year.
150. Use “recent” or “latest” with a date when you mean it.
