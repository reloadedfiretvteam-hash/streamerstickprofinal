# AEO Content Structure Practices (200+)

## Paragraph & P1 (first paragraph)

1. Keep P1 (first paragraph) to 40–60 words for featured snippet eligibility.
2. State the direct answer in the first sentence of P1.
3. Use the target question’s wording in the first sentence where natural.
4. Avoid filler phrases like “In this article we will…”
5. Put the most important fact (number, definition, date) in the first 15 words.
6. Use active voice in P1.
7. One main idea per paragraph in the first 3 paragraphs.
8. Front-load the answer; then add context or caveats.
9. Keep P1 under ~320 characters for paragraph snippet display.
10. Match P1 to the exact intent of the target query.
11. Use a number or stat in P1 when the query implies one (e.g. “how many”, “best”).
12. No rhetorical questions in P1; only direct statements.
13. Avoid “it depends” in P1 unless the query is explicitly conditional.
14. Use “is”/“are” definitions for “what is X” queries.
15. Use “to [verb]” or “you [verb]” for “how to” in P1.
16. Repeat the key term from the query once in P1.
17. Avoid multiple clauses in the opening sentence.
18. Prefer short sentences (under 25 words) in P1.
19. Use a colon or em dash to introduce the answer when it fits.
20. Ensure P1 is self-contained (readable without the rest of the page).

## Headings (H2/H3)

21. Use the exact question as H2 when targeting a PAA or featured snippet.
22. Start H2s with question words: What, How, Why, When, Where, Who, Which, Can, Is, Does.
23. Keep H2 under 70 characters for display.
24. One main question per H2; avoid compound questions.
25. Order H2s by user journey (what → how → why → comparison).
26. Use H3 for sub-answers or steps under an H2.
27. Mirror “People Also Ask” phrasing in H2s where relevant.
28. Use “How to [action]” for procedural queries.
29. Use “What is [term]” for definition queries.
30. Use “Best [category] for [context]” for commercial/compare queries.
31. Avoid vague H2s like “Overview” or “Introduction”; use specific questions.
32. Include the primary keyword in at least one H2.
33. Use numbered H2s for list-style snippets (e.g. “5 Ways to…”).
34. Keep heading hierarchy strict: one H1, then H2, then H3.
35. Use sentence case or title case consistently.
36. Avoid all-caps or excessive punctuation in headings.
37. Add schema-friendly headings (HowTo steps, FAQ questions).
38. Use “vs” or “or” in H2 for comparison queries.
39. Use “[Location] + [topic]” for local intent.
40. End question headings with a question mark.

## Lists & bullets

41. Use 3–6 items for list snippets when targeting PAA.
42. Start each bullet with a strong keyword or action verb.
43. Keep each bullet to 1–2 sentences (or one line) when possible.
44. Use ordered lists for steps; unordered for features/benefits.
45. Match list length to common snippet lengths (e.g. “5 best”, “7 steps”).
46. Use parallel structure (same grammatical form) in list items.
47. Put the most important item first when order isn’t procedural.
48. Avoid nested lists for snippet-targeted content when possible.
49. Use “First,” “Second,” “Finally” in step lists for clarity.
50. Add a one-line intro before the list that summarizes the answer.
51. Keep bullet text under 50 words per item for snippet eligibility.
52. Use numbers in list intros (e.g. “Here are 5 ways…”).
53. Avoid “and more” or “etc.” in the list itself.
54. Use list format for “what are the best”, “what are the types”.
55. Align list length with the query (e.g. “top 10” → 10 items).
56. Use bullets for “benefits of”, “reasons to”, “advantages”.
57. Use numbered list for “steps to”, “how to”, “guide”.
58. Add a short conclusion sentence after the list when helpful.
59. Ensure each list item is a complete thought.
60. Use consistent punctuation (e.g. no period on fragments, or period on full sentences).

## Tables

61. Use tables for “vs”, “comparison”, “difference between”.
62. Keep table to 3–7 columns for readability and snippet eligibility.
63. Use a clear header row (H3 or caption) that states the comparison.
64. Use the first column for the dimension (feature, price, etc.).
65. Keep cell content short (1 line when possible).
66. Use tables for “plans”, “pricing”, “features” when structured.
67. Add a one-sentence summary above or below the table.
68. Use consistent units and formats (e.g. all “Yes/No” or all “$”).
69. Avoid merged cells in snippet-targeted tables.
70. Use “Best for” or “Ideal for” in a column when comparing options.
71. Align table with “which is best”, “X vs Y” queries.
72. Include the target keyword in the table caption or header.
73. Keep row count reasonable (e.g. under 15 for readability).
74. Use tables for specs (e.g. device specs, channel counts).
75. Add schema (e.g. Table) if you use structured table markup.
76. Use consistent capitalization and formatting in cells.
77. Avoid tables for purely narrative content.
78. Use a table when the query implies a matrix (e.g. “compare X Y Z”).
79. Add alt text or caption for accessibility and context.
80. Prefer simple tables over nested or split tables for snippets.

## Length & density

81. Aim for 800–1,500 words for pillar pages that target multiple snippets.
82. Aim for 300–600 words for location/topic pages with one main snippet.
83. Keep FAQ answers to 40–60 words each.
84. Keep HowTo steps to 1–3 sentences each.
85. Avoid walls of text; use short paragraphs (2–4 sentences).
86. Use one idea per paragraph.
87. Add a table of contents (anchors) for long pages.
88. Place the most important content above the fold (first screen).
89. Use bullet summaries after long sections.
90. Avoid duplicate or near-duplicate paragraphs across pages.
91. Match content length to intent (short for definition, longer for guide).
92. Use internal links to related snippets (pillars, money pages).
93. Keep sentence length under 25 words on average for readability.
94. Use transition phrases between sections (“Next,” “Additionally”).
95. End with a clear CTA or next step when commercial.
96. Use “In summary” or “Bottom line” before a one-sentence takeaway.
97. Avoid padding; every paragraph should add information.
98. Use subheadings every 150–300 words for scannability.
99. Keep the first 100 words keyword-relevant and answer-focused.
100. Use word count as a guideline, not a target; clarity over length.

## Formatting & readability

101. Use bold for the key term in the first sentence of an answer.
102. Use one sentence per line in FAQs when it improves clarity (optional).
103. Use short paragraphs (2–3 sentences) in the first 3 sections.
104. Use line breaks between list items and between sections.
105. Avoid long parentheticals in snippet-targeted paragraphs.
106. Use “—” or “:” for definitions (e.g. “IPTV—Internet Protocol Television—is…”).
107. Use consistent terminology (e.g. “Fire Stick” vs “Firestick” sitewide).
108. Use numbers as digits (e.g. “18,000+”) for scannability.
109. Use “you” and “your” for direct address in how-to content.
110. Avoid jargon in P1; define it in the next sentence if needed.
111. Use bullet points for 3+ items instead of inline commas.
112. Use numbered steps for any sequential process.
113. Use blockquote only for real quotes; not for emphasis.
114. Use italics sparingly (e.g. product names, terms).
115. Ensure contrast and font size meet accessibility guidelines.
116. Use descriptive link anchor text (e.g. “best IPTV for Fire Stick”).
117. Avoid “click here” or “read more” as sole anchor.
118. Use consistent date format (e.g. “2026” in titles).
119. Use “e.g.” and “i.e.” sparingly in snippet-targeted text.
120. Prefer “and” over “&” in body text for voice/snippet clarity.

## Answer placement & order

121. Place the direct answer in the first 100 words of the section.
122. Order FAQs by frequency or user journey, not alphabetically only.
123. Put the most common question first in FAQ blocks.
124. Place “What is X” before “How does X work” when both exist.
125. Put comparison or “best” content after definition content.
126. Place location-specific content (e.g. “[City] IPTV”) after the general answer.
127. Order steps chronologically; don’t skip steps.
128. Put pricing or “cost” after value proposition when commercial.
129. Place “how to set up” after “what you need”.
130. Put troubleshooting or FAQ after the main how-to.
131. Order list items by importance or by query (e.g. “best” = best first).
132. Place CTA after the main answer, not before.
133. Put “summary” or “bottom line” at the end of the section or page.
134. Order PAA-style questions to match the cluster’s priority keywords.
135. Place internal links to pillars after the first 1–2 paragraphs.
136. Put “related questions” or “see also” at the end.
137. Order location pages by country/region if you have a geo structure.
138. Place trust signals (reviews, uptime) near CTA.
139. Put author or date after the main content when using E-E-A-T.
140. Order schema (FAQ, HowTo) to match the order of on-page content.

## Snippet-specific (paragraph)

141. Target one primary snippet per section (one clear paragraph).
142. Start the paragraph with the answer, not context.
143. Use 40–50 words for definition snippets.
144. Use 50–60 words for “how” or “why” when a short explanation fits.
145. Avoid starting with “Yes” or “No” unless the query is yes/no.
146. Use a full sentence for the first sentence of the snippet block.
147. Ensure the paragraph is a single block (no lists inside) for paragraph snippet.
148. Remove redundant sentences from the target paragraph.
149. Use the same wording as the H2 question in the first sentence when natural.
150. Test with “site:yoursite.com [query]” to see what Google might use.

## Snippet-specific (list)

151. Use exactly 3, 5, 7, or 10 items when the query implies a number.
152. Add a one-sentence intro that includes the query and the number (e.g. “Here are 5 ways to…”).
153. Keep each list item to one line when targeting list snippets.
154. Use parallel structure so the snippet reads cleanly.
155. Put the strongest item first for “best” queries.
156. Use bullets for “types of”, “ways to”, “benefits of”.
157. Use numbers for “steps”, “reasons”, “tips”.
158. Avoid sub-bullets in the main list for snippet.
159. Ensure the list is the only list in that section (or the first).
160. Match list type (ul vs ol) to content (steps = ol).

## Snippet-specific (table)

161. Use a simple 2–4 column table for “X vs Y”.
162. Use the first column for the criterion (e.g. “Price”, “Channels”).
163. Keep cell text under 10 words when possible.
164. Use a clear H2 or caption above the table with the query.
165. Add one sentence below the table summarizing the “winner” or “best for”.
166. Avoid empty cells; use “—” or “N/A” if needed.
167. Use consistent formatting (all dollars, all “Yes/No”).
168. Place the table after a short intro paragraph.
169. Ensure the table is the only table in that section for clarity.
170. Use header row that matches the query (e.g. “Fire Stick 4K | Fire Stick 4K Max”).

## Multi-snippet pages

171. Target 3–5 snippets per pillar page (different H2s).
172. Target 1–2 snippets per location page (P1 + one FAQ block).
173. Avoid targeting the same query on multiple pages (canonical, one page per query).
174. Use internal links from snippet pages to money pages.
175. Vary snippet format (one paragraph, one list, one table) per page when relevant.
176. Ensure no two sections compete for the same snippet (different questions).
177. Use a content brief that lists target query + desired snippet type per H2.
178. Update snippet-targeted paragraphs when SERP or PAA changes.
179. Monitor “Position 0” in GSC or third-party tools per target query.
180. A/B test P1 length (40 vs 60 words) if you have traffic to test.

## Location & entity

181. Include the location name in the H1 and P1 for local pages.
182. Use “[City] IPTV” or “[City] jailbroken Fire Stick” as the main keyword.
183. Keep one primary location per page (no “and nearby cities” in the main snippet).
184. Use region/country in breadcrumbs and schema.
185. Add location to meta title and description.
186. Use “in [location]” or “for [location]” in the first sentence when relevant.
187. Place location in the opening of the P1 for local intent.
188. Use consistent location format (e.g. “Houston” not “Houston, TX” in H1 if you prefer short).
189. Add state/country in schema (e.g. address or areaServed).
190. Use location in at least one H2 (e.g. “IPTV in [City]”).

## Freshness & updates

191. Use “2026” or current year in titles for “best 2026” queries.
192. Update P1 when the answer changes (e.g. new product, price).
193. Add “Last updated” or date in schema when you change the page.
194. Refresh FAQ answers when the product or policy changes.
195. Avoid “coming soon” or “TBD” in snippet-targeted content.
196. Update list order when “best” changes (new entrant, test).
197. Review PAA questions quarterly and add new FAQs.
198. Update HowTo steps when the product UI changes.
199. Remove outdated stats or dates from P1 and FAQs.
200. Use changelog or “What’s new” for major updates; keep P1 stable.
