# AEO Featured Snippet Format Practices (150+)

## Paragraph snippet

1. Write one clear paragraph of 40–60 words that answers the query.
2. Put the answer in the first sentence.
3. Use a full sentence, not a fragment, for the opening.
4. Stay under ~320 characters for the paragraph.
5. Avoid lists or sub-bullets inside the target paragraph.
6. Use one idea per paragraph.
7. Match the paragraph to the H2 question above it.
8. Use “is”/“are” for definition queries.
9. Use “to [verb]” or “[subject] [verb]” for how-to.
10. Remove filler (“In conclusion,” “It is important to note”).
11. Use active voice.
12. Include the keyword once in the paragraph.
13. Prefer 2–3 short sentences over one long sentence.
14. Avoid “however” or “but” in the first sentence.
15. Use a period, not a comma, before “and” in the opening when possible.
16. Test: read the paragraph aloud; it should stand alone as an answer.
17. For “what is X”: Definition + one sentence of context.
18. For “how does X work”: Mechanism in 1–2 sentences.
19. For “why X”: Reason + one supporting point.
20. For “when/where”: Direct answer + optional qualifier.

## List snippet (bullet)

21. Use 3–6 items for “ways,” “types,” “benefits,” “reasons.”
22. Use 5–10 items when the query implies a number (“top 10,” “5 ways”).
23. Start each item with a keyword or action verb.
24. Keep each item to one line (under ~15 words) when possible.
25. Use parallel structure (same grammar).
26. Add a one-sentence intro that includes the query and number.
27. Put the strongest item first for “best” queries.
28. Use unordered list (bullets) for non-sequential items.
29. Use ordered list (numbers) for steps or ranked “best.”
30. Avoid sub-bullets in the main list.
31. Ensure the list is the first list in that section.
32. Match list length to the query (“7 steps” → 7 items).
33. Use “First,” “Second,” “Finally” only in step lists.
34. Keep list intro under 30 words.
35. Don’t mix bullet and number in the same list.
36. Use consistent punctuation (all with or all without period).
37. Ensure each item is a complete thought.
38. For “what are the types”: One type per bullet.
39. For “how to”: One step per number.
40. For “best X”: One item per bullet with a short reason.

## List snippet (numbered steps)

41. Use 3–10 steps for how-to.
42. One action per step.
43. Start each step with a verb (Install, Open, Enter, Click).
44. Keep each step to 1–2 sentences.
45. Order steps chronologically.
46. Add a one-sentence intro (“Here’s how to…”).
47. Use “Step 1,” “Step 2” or “1.” “2.” consistently.
48. Avoid skipping steps (no “then” that implies a missing step).
49. Include prerequisites in the intro or step 1.
50. End with a confirmation step (“You should see…”).
51. Use present tense or imperative.
52. Keep steps scannable (short sentences).
53. Add time estimate in intro if helpful (“in 5 minutes”).
54. For setup: device → app → credentials → test.
55. For comparison: criteria → option A → option B → recommendation.
56. Ensure steps are in the right order (no “before you do step 1” in step 3).
57. Use the same format for each step (e.g. all imperative).
58. Avoid “optional” steps in the main list; put them after.
59. Add a “Troubleshooting” section after the steps, not inside.
60. Match step count to the query (“5 steps” → 5 steps).

## Table snippet

61. Use for “X vs Y,” “comparison,” “difference.”
62. Use 2–4 columns (e.g. Feature, Option A, Option B).
63. Use a clear header row.
64. First column = dimension (Price, Channels, Devices).
65. Keep cell content under 10 words.
66. Use consistent units (all $ or all “Yes/No”).
67. Add a one-sentence summary above or below.
68. Use a descriptive H2 or caption with the query.
69. Avoid empty cells; use “—” or “N/A.”
70. Use simple table structure (no merged cells for snippet).
71. Match table to “compare,” “vs,” “difference between.”
72. Use “Best for” row when comparing options.
73. Keep to 3–10 rows for readability.
74. Use the same formatting in every cell (e.g. bold only in headers).
75. Place the table after a short intro paragraph.
76. For “which is best”: include a “Verdict” or “Best for” row.
77. Use consistent capitalization.
78. Ensure the table is the only table in that section.
79. Add caption or aria-label for accessibility.
80. For pricing: one row per plan or one column per plan.

## HowTo snippet

81. Use HowTo schema with steps.
82. Each step: name + text (and optional image).
83. Use 3–10 steps.
84. Add totalTime (e.g. PT10M) when relevant.
85. Step name = short action (“Install the app”).
86. Step text = 1–2 sentences.
87. Use same order as on-page numbered list.
88. Match schema steps to visible steps exactly.
89. Use one HowTo per page when possible.
90. Add “name” and “description” at the top level.
91. For setup guides: prerequisites in description.
92. Use ISO 8601 for duration (PT5M, PT30M).
93. Don’t use HowTo for non-procedural content.
94. Ensure steps are actionable (user can do them).
95. Add image URL to steps when you have visuals.
96. Keep step text under 50 words each.
97. Use “Prepare,” “Install,” “Configure,” “Test” style names.
98. Match HowTo to “how to [action]” queries.
99. One HowTo per main task (e.g. one for setup, one for troubleshooting).
100. Validate with Google Rich Results Test.

## FAQ snippet

101. Use FAQPage schema with Question + acceptedAnswer.
102. Each answer 40–60 words.
103. Use the exact question as “name” in schema.
104. Use the visible answer as “text” in schema (content parity).
105. 5–10 FAQs per page for rich results.
106. Order by importance or user journey.
107. One FAQ block per page (or one per section with one schema).
108. Avoid duplicate FAQs across pages (canonical, one page per query).
109. Use full sentences in answers.
110. Match FAQ to PAA questions in your niche.
111. Add new FAQs when you see new PAA questions.
112. Keep tone consistent (e.g. all “you” or all “users”).
113. Use “Answer” type with “text” (not HTML).
114. Don’t use FAQ for non-Q&A content.
115. Ensure no hidden content (schema = visible).
116. Use question mark in question text.
117. Avoid “FAQ” or “Q:" in the question name.
118. Keep answers factual and verifiable.
119. Update FAQ when product or policy changes.
120. Validate with Google Rich Results Test.

## Definition / “What is” snippet

121. First sentence = definition (X is…).
122. Second sentence = context or example.
123. Use 40–50 words total.
124. Include the term in the first sentence.
125. Use “is” or “are” (e.g. “IPTV is…”).
126. Avoid “refers to” in the first 5 words when you can use “is.”
127. Add one concrete detail (number, example).
128. No rhetorical questions in the definition block.
129. Use commas or em dash for inline definition.
130. Match the definition to the query wording.

## “Best” / list snippet (product/service)

131. Use “Best [X] for [Y]” in the H2.
132. One paragraph intro with the number (e.g. “Here are the 5 best…”).
133. One item per bullet with name + one-line reason.
134. Put #1 first.
135. Use consistent structure (name, then why).
136. Keep each item to 1–2 lines.
137. Add a short conclusion (“Best overall: …”).
138. Match list length to query (“top 5” → 5).
139. Use “Best for [use case]: [name]” when comparing.
140. Include a “Also consider” or “Runner-up” if space.

## Video / HowTo video snippet

141. Use VideoObject schema when you have a video.
142. Include name, description, thumbnailUrl, uploadDate.
143. Add duration in ISO 8601 (PT5M30S).
144. Use HowTo + video in step when applicable.
145. Match video title to target query.
146. Use a clear thumbnail.
147. Add transcript or captions when possible.
148. Keep description to 1–2 sentences.
149. Use same topic as the page (no off-topic videos).
150. Validate VideoObject with Rich Results Test.
